# Product Decisions

This document records important product decisions made during the design of Programming Mastery.

Unlike Architecture Decision Records (ADRs), these decisions focus on the learner experience, product behavior, and long-term design philosophy.

---

# PD-001

## Title

Programming Mastery is a Personalized Learning Platform

## Status

Accepted

## Decision

Programming Mastery is not a traditional course website.

It is a personalized learning platform that adapts to each learner based on:

- Goals
- Current knowledge
- Learning speed
- Weak areas
- Study time
- Progress

## Why

Different learners have different objectives.

Some want a job.

Some want to build projects.

Some only want to learn React.

Some only want interview preparation.

The platform should adapt instead of forcing everyone through the same path.

## Impact

- Personalized dashboard
- Adaptive recommendations
- Resume learning
- Smart revision
- Progress tracking
- Learning analytics
- Gamification

# PD-002

## Title

Learning Should Feel Rewarding, Not Like Homework

## Status

Accepted

## Decision

Every interaction should give the learner a sense of progress.

Rewards should reinforce learning rather than distract from it.

## Why

Motivation is easier to maintain when learners can clearly see their improvement.

The platform should celebrate meaningful milestones instead of encouraging endless clicking.

## Impact

- Skill mastery
- XP
- Achievements
- Progress visualization
- Streaks
- Milestones
